# netskope_gre_tunnel (Resource)

Manages a Netskope GRE (Generic Routing Encapsulation) tunnel. GRE tunnels connect a network device (router, firewall, or SD-WAN appliance) to a Netskope Point of Presence (POP) for inline traffic steering and inspection.

## GRE vs IPSec

| | GRE | IPSec |
|---|---|---|
| Encryption | None (relies on underlying network security) | Yes (IKEv2) |
| Overhead | Low | Higher |
| Use case | Internal networks where encryption is handled elsewhere | Internet-facing tunnels requiring encrypted transport |

## Choosing a POP

Use the [`netskope_grepop`](../data-sources/grepop) or [`netskope_grepo_ps_list`](../data-sources/grepo_ps_list) data source to look up available POP names:

```hcl
data "netskope_grepo_ps_list" "all" {}
```

## X-Forwarded-For (XFF)

Enable `options.xff.xff_enabled` to insert the original client IP into the XFF header. Use `xff_ip_list` to restrict which source IPs are trusted for XFF insertion.

## Example Usage

```terraform
resource "netskope_gre_tunnel" "my_gretunnel" {
  bandwidth = 0
  enabled   = false
  notes     = "...my_notes..."
  options = {
    xff = {
      xff_enabled = false
      xff_ip_list = [
        "..."
      ]
    }
  }
  pop_names = [
    "..."
  ]
  site        = "...my_site..."
  source_ip   = "...my_source_ip..."
  source_type = "Machine"
  template    = "...my_template..."
  vendor      = "...my_vendor..."
}
```
