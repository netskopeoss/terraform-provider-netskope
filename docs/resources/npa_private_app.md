# netskope_npa_private_app (Resource)

Manages an NPA private application. Private apps can be configured for **client-based** access (via the Netskope client/tunnel) or **clientless browser-based** access (via the Netskope portal).

## Client-Based vs Clientless Access

| | Client-Based | Clientless (Browser) |
|---|---|---|
| `clientless_access` | `false` (default) | `true` |
| `private_app_protocol` | Not needed | **Required** (`"http"` or `"https"`) |
| `private_app_hostname` | Set by user | Auto-generated by Netskope |
| `allow_unauthenticated_cors` | Typically `false` | Typically `true` |
| Endpoint requirement | Netskope client installed | Browser only |

### `protocols` vs `private_app_protocol`

These two fields serve different purposes:

- **`protocols`** — Transport-layer definition (port + tcp/udp). Required for all private apps regardless of access mode.
- **`private_app_protocol`** — Application-layer scheme (`"http"` or `"https"`) used by the backend service. Only required when `clientless_access = true`. Requires replacement if changed.

## Example Usage

```terraform
# Client-based private app (accessed via NPA client/tunnel)
#
# When clientless_access = false (the default), traffic is routed through
# NPA publishers via the Netskope client. The "private_app_protocol" field
# is NOT needed — only "protocols" (transport-layer port/protocol) is required.

resource "netskope_npa_private_app" "client_app" {
  private_app_name        = "internal-api"
  private_app_hostname    = "api.internal.example.com"
  real_host               = "api.internal.example.com"
  use_publisher_dns       = true
  clientless_access       = false
  trust_self_signed_certs = false

  protocols = [
    {
      port     = "443"
      protocol = "tcp"
    }
  ]

  publishers = [
    {
      publisher_id   = "12345"
      publisher_name = "pub01.local"
    }
  ]

  tags = [
    {
      tag_name = "production"
    }
  ]
}

# Clientless (browser-based) private app
#
# When clientless_access = true, the app is accessed directly in a browser
# via the Netskope portal — no NPA client is needed on the endpoint.
#
# In this mode, "private_app_protocol" IS REQUIRED. It specifies the
# application-layer scheme (e.g. "https" or "http") that the backend
# service speaks. This is separate from "protocols", which defines the
# transport-layer port and protocol (tcp/udp).
#
# Key differences from client-based apps:
#   - private_app_protocol is required (e.g. "https")
#   - private_app_hostname is auto-generated by Netskope (do not set)
#   - allow_unauthenticated_cors is typically set to true
#   - real_host is the internal hostname the browser will connect to

resource "netskope_npa_private_app" "browser_app" {
  private_app_name           = "internal-wiki"
  real_host                  = "wiki.internal.example.com"
  clientless_access          = true
  private_app_protocol       = "https"
  trust_self_signed_certs    = false
  allow_unauthenticated_cors = true

  protocols = [
    {
      port     = "443"
      protocol = "tcp"
    }
  ]

  publishers = [
    {
      publisher_id   = "12345"
      publisher_name = "pub01.local"
    }
  ]

  tags = [
    {
      tag_name = "production"
    }
  ]
}
```
