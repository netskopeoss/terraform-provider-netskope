# netskope_rbac_role_config (Data Source)

Returns the RBAC role configuration catalog for the tenant. Use this data source to resolve API group names to their tenant-specific numeric IDs when building [`netskope_rbac_role`](../resources/rbac_role) resources.

## Why Use This Data Source?

`netskope_rbac_role` requires numeric `api_group_id` values per permission entry. These IDs are **tenant-specific** — the same API group has a different ID on each Netskope tenant. Hardcoding them makes role configs non-portable across tenants (dev/staging/prod) and breaks when a new tenant is provisioned.

This data source solves that by letting you reference API groups by their stable internal `name` (e.g. `"events_alerts"`, `"npa_pub"`) instead:

```hcl
data "netskope_rbac_role_config" "this" {}

locals {
  api_group_id = {
    for g in data.netskope_rbac_role_config.this.api_groups : g.name => g.api_group_id
  }
}

resource "netskope_rbac_role" "helpdesk" {
  name = "helpdesk-readonly"
  api_groups = [{
    api_group_id = local.api_group_id["events_alerts"]
    permission   = "r"
  }]
}
```

The `api_group_id` map is rebuilt on every plan, so configs remain correct if IDs change (e.g. after a tenant migration).

## What This Data Source Exposes

### `api_groups`

The full list of API groups available on the tenant. Each entry has:

- `api_group_id` — tenant-specific numeric ID (use this in `netskope_rbac_role`)
- `name` — stable internal name to use as the map key (e.g. `"events_alerts"`, `"npa_pub"`)
- `display_name` — human-readable name shown in the Netskope UI
- `highest_permission` — maximum permission level this group supports (`"r"`, `"rw"`, or `"rwa"`)

### `obfuscation`

The catalog of data-field obfuscation options. Each entry is keyed by `api_group_id` and has an `obfuscation_name` (e.g. `"user"`, `"source"`, `"userip"`, `"file"`, `"app"`) that maps to the `properties` list in an `netskope_rbac_role` obfuscation block.

Use this to build an obfuscation field list without hardcoding field names:

```hcl
locals {
  # For each api_group, list all obfuscatable field names (excluding "app")
  obfuscation_fields = {
    for g in data.netskope_rbac_role_config.this.api_groups :
    g.name => [
      for o in data.netskope_rbac_role_config.this.obfuscation :
      o.obfuscation_name if o.api_group_id == g.api_group_id && o.obfuscation_name != "app"
    ]
  }
}
```

### `functions`

UI function groupings that map the Netskope administration UI sections (e.g. `"Network"`, `"Administration"`) to their constituent API group IDs via `sub_functions`. Useful for understanding the UI hierarchy or for constructing roles that mirror a UI-visible category, but not required for basic role creation.

## Example Usage

```terraform
data "netskope_rbac_role_config" "this" {}

locals {
  # Build a name -> tenant-specific ID map for all API groups.
  # API group IDs are tenant-specific and cannot be hardcoded portably.
  api_group_id = {
    for g in data.netskope_rbac_role_config.this.api_groups : g.name => g.api_group_id
  }

  # Build a map of api_group name -> list of obfuscatable field names, excluding "app"
  # (keeps "App names, URLs, and destination IPs" readable; obfuscates user, source, userip, file)
  obfuscation_fields = {
    for g in data.netskope_rbac_role_config.this.api_groups :
    g.name => [
      for o in data.netskope_rbac_role_config.this.obfuscation :
      o.obfuscation_name if o.api_group_id == g.api_group_id && o.obfuscation_name != "app"
    ]
  }
}

resource "netskope_rbac_role" "helpdesk" {
  name        = "helpdesk-readonly"
  description = "Read-only helpdesk role with privacy obfuscation"

  api_groups = [{
    api_group_id = local.api_group_id["events_alerts"]
    permission   = "r"
    obfuscation = {
      properties = local.obfuscation_fields["events_alerts"]
    }
  }]
}
```
